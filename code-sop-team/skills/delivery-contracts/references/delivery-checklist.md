# 交付验收七维清单

用法：逐项勾选，每条结论带 `file:line`；**Blocker 未清不得 release**。只勾「证据到位的项」，不勾「看起来没问题」。

前置：读项目特化路径（design token · i18n 库 · OpenAPI · 浏览器走查默认 URL）与 plan 的 Done when。

## 1 视觉一致性

**合格判据**：视觉参数与 design system、邻近页面同源，不靠肉眼微调。

- [ ] 字体大小、字重、行高与 design system / 邻近页面一致
- [ ] 颜色来自 token/变量，无 scattered 硬编码（grep `#`、`rgb(`、魔法数 px 字号）
- [ ] 间距、圆角、阴影与组件库或现有页面一致
- [ ] 响应式 / 暗色（若项目有）未遗漏
- [ ] 未落入无 brief 时的三套默认：暖奶油底+衬线大标题 / 纯黑+acid 强调 / 报纸式细线零圆角；若 brief 未要求 → 改一轴
- [ ] 有一个 signature 元素，其余克制；字体配对与动效服务主题，非 scattered 装饰

**不通过处理**：硬编码色值 → 要求换 token；纯风格偏差 → 可开 issue，不挡 release；命中三套默认且 brief 未要求 → 至少改一轴再交付。

## 2 i18n 与文案

**合格判据**：用户可见文案只有一个真源，新增 key 所有活跃 locale 齐全。

- [ ] 文案走 i18n API（`t` / `$t` / `useTranslation`），无硬编码上屏（debug 占位须有 ticket）
- [ ] 无遗漏字面量（grep 中英文 UI 字符串 vs key 文件）
- [ ] 新增 key 在各 locale 文件齐全，无空翻译；fallback 策略写清
- [ ] 日期、数字、复数格式符合 locale；错误 / toast / 空态文案同样走 i18n
- [ ] 改按钮或菜单文案时同步 `aria-label` · `data-testid` · Playwright 选器 · 手册配图锚点
- [ ] 同概念全站统一称谓（「批次」vs「batch」不混用）
- [ ] 改 i18n 库或 locale 目录时同步更新项目特化路径文档

**不通过处理**：只改组件不改 locale、验收脚本写死旧文案 → 要求同 PR 补齐；第三次「对齐文案」hotfix → 转 plan 做术语收敛 TASK。跳过（纯内部 CLI、无 UI、书面确认不交付多语言）须在报告写明，且仍检查无硬编码散落与术语一致。

## 3 文档 ↔ 实现

**合格判据**：文档说的已实现，实现的已写进文档，双向都能查到。

- [ ] 规格 / README / 用户文档描述的行为，代码已实现
- [ ] 已实现能力在文档中有对应说明，非仅代码自解释
- [ ] 公开 API / CLI / 配置变更同 PR 更新 README 与 docs；示例可运行或标 deprecated
- [ ] 修改文件内的断链已修复；相关 doc 双向互链，索引有入口
- [ ] 主文档版本头与 CHANGELOG 大改同步；脚本化（`verify_doc_*.sh`：断链 · 版本锚点 · 防回退 grep）与人工语义各走一遍

**不通过处理**：冲突标 `Decision needed`（文档说法 · 实现现状 · 建议 · 等你决策），拍板后再改文档或代码。脚本绿不等于通过——语义完整、读者可读须人工判定。

## 4 API 与数据

**合格判据**：前后端可并行对接，字段与实现零歧义。

- [ ] 接口文档（OpenAPI / README）含示例请求响应、错误码表、鉴权说明
- [ ] 字段、类型、枚举、分页风格完整无歧义
- [ ] 实现与文档一致（跑 api skill 子集核对）
- [ ] DB / schema / migration 与文档一致：命名一致、必要索引、FK 有意图、nullable 有说明、无无界 JSON blob
- [ ] Mock / fixture 与生产 schema 一致

**不通过处理**：字段缺失或文档与实现不一致 → 标 `Decision needed`（文档说法 · 实现现状 · 建议）上报；不擅自改 spec 迁就实现。

## 5 组件与交互完整度

**合格判据**：生产路径上没有 demo 级交互，每个状态都有 UI。

- [ ] 主要页面能一句话说出主工作流意图，无多工作流并列主 CTA
- [ ] 角色有差异时，默认着陆 / 侧栏权重与 RBAC 一致
- [ ] 跨页协作经分支点（深链 / `from` / 来源条），不把无关工作流表单塞进 drawer；多步交付有可辨识实体上下文（顶栏或面包屑中的当前对象）
- [ ] 无「待办/占位」类注释留在生产路径
- [ ] 操作有即时反馈（hover / focus / disabled / loading），非静态假按钮
- [ ] 加载 / 空态 / 错误态有 UI，非白屏或 `console.log`
- [ ] 表单校验、禁用态、提交反馈完整；Dialog / Drawer 非 demo 级（标题、确认、取消、遮罩 / ESC 符合预期）

**不通过处理**：假按钮、空态缺失、白屏 → 补齐后再交付；结构性导航问题回流 ia，非结构抛光留在本清单。

## 6 可维护性

**合格判据**：改动落在正确层次，能被最小 diff 描述。

- [ ] 新功能落在正确模块层，未破坏现有分层
- [ ] 改动能用最小 diff 描述，无无关 drive-by 重构
- [ ] 配置 / 特性开关（若有）便于扩展，未把可配置项写死

**不通过处理**：夹带无关重构 → 要求拆成独立改动；分层错位回流架构评审，不带病发版。

## 7 生产就绪

**合格判据**：生产路径干净，日志可对外，验收数字可复现。

- [ ] 无 debug 开关、mock 数据、测试账号残留于生产路径
- [ ] 权限 / 鉴权与 security 要点一致
- [ ] 日志不含 PII / 密钥；错误信息对用户友好
- [ ] 与 `./scripts/verify.sh` 或项目 verify 结果一致（已绿）
- [ ] 依赖升级类变更注明 breaking 与回滚路径

**不通过处理**：mock / debug / 测试账号残留、PII 或密钥入日志 → 清理后复验，不得进 release；verify 未绿不得给出交付结论，先回 verify。

## 结论模板

- 通过：`七维无 Blocker；High 已在本 Sprint 内闭环`（列出 Medium、Low 去向）。
- 不通过：逐条列出 Blocker 与 `Decision needed`，等用户决策后再放行。
