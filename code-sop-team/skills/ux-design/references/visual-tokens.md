# 视觉规范（token）

**禁止在组件里写 magic number。** 所有视觉值来自一套 token。

| 类别 | 要求 |
|---|---|
| 间距 | 4 或 8 的倍数，4–6 档够用（4/8/12/16/24/32） |
| 字号 | 4–5 档（如 12/14/16/20/28），层级靠字号+字重，不靠多档混用 |
| 颜色 | 语义命名（`text-primary` / `bg-surface` / `danger`），不用 `gray-300` 直引 |
| 层级 | z-index 集中一张表，见 `patch-loop.md` 弹窗分层 |
| 圆角/阴影 | 各 2–3 档，多了就是不统一 |

## 三条硬规矩

1. **一屏只有一个主按钮**。两个 primary = 没有 primary。
2. **文字对比度 ≥ 4.5:1**（正文）。浅灰字在浅底上是最常见的可用性事故。
3. **深色主题单独核对**：不要把浅色主题的颜色直接反相，要单独定语义色。

## token 的最小集合

一个够用的 token 集不需要上百个变量。下面这些覆盖 90% 场景：

```
/* 间距 */
--space-1: 4px   --space-2: 8px   --space-3: 12px
--space-4: 16px  --space-6: 24px  --space-8: 32px

/* 字号 */
--text-xs: 12px  --text-sm: 14px  --text-base: 16px
--text-lg: 20px  --text-xl: 28px

/* 语义色（深/浅主题各一套值，名字不变） */
--text-primary  --text-secondary  --text-muted
--bg-surface    --bg-elevated     --border-default
--accent        --danger           --warning        --success

/* 层级 */
--z-dropdown: 100  --z-modal: 200  --z-toast: 300  --z-tooltip: 400
```

**名字表达用途，值表达外观。** 换主题时只换值，组件代码一行不改。

## 深色主题的三个坑

| 坑 | 症状 | 改法 |
|---|---|---|
| 直接反相 | 阴影变成光晕、图片刺眼 | 深色下用更低对比的边框替代阴影 |
| 纯黑底 (#000) | 与纯白字对比过强，久看疲劳 | 用 #0a—#1a 区间的深灰/深青做底 |
| 语义色沿用浅色值 | 深底上红绿都看不清 | 深色主题下提高亮度、降饱和度 |

## 走查方法

改完一屏，随机抽 5 个元素，问「这个值来自 token 还是我现编的」。有一个是现编的，就说明 token 没被当规矩用。
