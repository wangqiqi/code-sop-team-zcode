# 信息架构与交互流程

## 一、先定位在哪一层（Garrett 五层）

| 层 | 问什么 | 出问题时的症状 |
|---|---|---|
| 战略 | 给谁、解决什么 | 做了一堆没人用的功能 |
| 范围 | 这次做哪些 | 需求无限膨胀 |
| **结构（IA）** | 内容怎么组织、从哪进 | 用户找不到入口 |
| **骨架（交互）** | 点了之后发生什么 | 流程走不通、状态丢失 |
| **表现（视觉）** | 长什么样 | 看不清、不一致 |

**先定层再动手。** 在视觉层反复调色，但问题是结构层入口不对——怎么调都不会好用。

## 二、信息架构（IA）

### 三条只做不说的规则

1. **一个功能只有一个主入口**。两个入口可以，但必须主次分明；平级双入口会让用户以为它们是两件事。
2. **导航深度 ≤3 层**。第 4 层开始，用户基本靠搜索而不是浏览。
3. **按用户任务分组，不按系统实现分组**。用户找"看今天要巡哪些点"，不是找"巡检记录表"。

### 角色入口表

多角色系统（如管理端 / 现场端）先画一张表：

| 角色 | 进来第一件事 | 高频操作 | 不该看到 |
|---|---|---|---|
| 管理员 | 看总览与异常 | 审批、配置 | 具体作业细节 |
| 现场人员 | 看今天任务 | 打卡、上报 | 全局统计、他人数据 |

**"不该看到"这一列比"该看到"更重要**——它同时是信息架构和权限设计。

### 反模式

| 反模式 | 症状 |
|---|---|
| 平铺 20 个一级菜单 | 用户每次都要扫一遍 |
| 菜单名用系统术语 | "数据维护" "参数配置" |
| Dashboard 塞满图表 | 没有一个能回答问题 |
| 面包屑与实际导航不一致 | 用户不敢点返回 |

## 三、交互流程

一条流程必须写清四件事：

1. **起点**：用户从哪个界面、什么状态下进入
2. **主路径**：点击 → 反馈 → 下一步（每步都要有反馈）
3. **分支**：失败、取消、返回、权限不足
4. **终点**：完成后看到什么，怎么再回到主流程

### 分支点（最容易漏）

| 分支 | 必须回答 |
|---|---|
| 用户取消 | 已填数据保不保留？ |
| 请求失败 | 能重试吗？重试会重复提交吗？ |
| 中途离开 | 回来还在原处吗？ |
| 无权限 | 是隐藏、置灰、还是提示申请？ |
| 并发冲突 | 别人先改了，我这边显示什么？ |

**没有分支设计的流程不算设计完。**

## 四、状态放哪（单一真相源）

前端出现「同一个状态两处各存一份」是体验 bug 的根源：

| 反模式 | 症状 | 改法 |
|---|---|---|
| UI 本地 state 与 URL 各存一份筛选条件 | 刷新后筛选丢失 / 分享链接不对 | URL 是唯一源，本地只做派生 |
| 列表数据和详情各拉一次接口 | 改完详情列表不刷新 | 单一数据源 + 变更后重取 |
| 权限前端判断 + 后端判断两套逻辑 | 前端能点后端报 403 | 以后端为准，前端只做展示 |

状态归属定不清，加多少 loading 和刷新都救不回来。
